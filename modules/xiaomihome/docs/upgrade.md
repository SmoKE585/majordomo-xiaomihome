# Обновление

Модуль ставится поверх прежней версии. **Схема БД не меняется:** таблицы
`xidevices`, `xicommands`, `xiqueue` и все привязки остаются на месте.

## Что сохраняется

- названия устройств, SID, типы, ключи шлюзов;
- значения и привязки свойств;
- очередь команд;
- настройки модуля в `project_modules.DATA`; новые ключи получают значения по
  умолчанию (`ALIVE_MINUTES = 0`, округление — сотые).

## Что изменилось

- интерфейс переведён на `MDJUI` (`md-*`), тёмную тему и ширину 390 px;
- чистые адреса `/panel/xiaomihome/...`, старые `view_mode`-ссылки работают;
- цикл обрабатывает сообщения в своём процессе, без HTTP-запроса к
  `/ajax/xiaomihome.html?op=process`;
- появился тип-aware порог доступности и живое обновление списка каждые 8 секунд;
- в настройках появился порог доступности и bind IP с проверкой;
- ключ шлюза вводится как секрет и не выводится в интерфейсе;
- удалены старые `.html`-шаблоны, CSS и AJAX-перерисовка списка;
- добавлена документация для «Базы знаний».

## Совместимость

- Старые ссылки `?action=xiaomihome&view_mode=search_xidevices`,
  `edit_xidevices`, `update_settings` открываются.
- Удаление через `view_mode=delete_xidevices` больше не выполняется по GET:
  открывается карточка устройства, удаление подтверждается формой.
- AJAX-операция `op=process` прежней версии удалена: её вызывал только старый
  цикл. Если вы обновляете папку `modules/xiaomihome` вручную, замените и
  `scripts/cycle_xiaomihome.php`.
- Новый AJAX `op=rows` отдаёт JSON для живого списка; он только читает данные.

## Что проверить

1. Откройте «Xiaomi Home»: устройства и привязки на месте.
2. В карточке шлюза убедитесь, что ключ задан.
3. Запустите цикл и проверьте X-Ray: ошибок bind быть не должно.
4. Нажмите «Опросить» у устройства и дождитесь значений.
