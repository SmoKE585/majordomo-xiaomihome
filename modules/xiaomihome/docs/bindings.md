# Свойства и привязки

## Таблица свойств

Каждая строка `xicommands` — одна метрика или команда:

- `TITLE` — ключ протокола (`temperature`, `channel`, `battery_level`, …);
- `VALUE` — последнее значение;
- `UPDATED` — когда обновилось;
- `LINKED_OBJECT`, `LINKED_PROPERTY`, `LINKED_METHOD` — привязка.

Служебные строки (`report`, `heartbeat`, `read_ack`, `iam`, `ip`) показываются
на вкладке «Обзор» в блоке технических сообщений и помечены в таблице как
технические. Привязывать их обычно не нужно.

## Привязка

1. Откройте свойство в таблице.
2. Выберите объект, свойство объекта и при необходимости метод.
3. Сохраните.

Когда шлюз присылает событие, значение пишется в свойство объекта. Когда
свойство объекта меняется из сценария или панели, модуль ставит команду шлюзу в
очередь. Повтор того же значения команду не отправляет.

Метод получает параметры `PROPERTY`, `OLD_VALUE`, `NEW_VALUE`, а также «сырые»
поля события шлюза.

## Команды

| Свойство | Что отправляет |
| --- | --- |
| `channel`, `channel_0`, `channel_1` | включение/выключение реле |
| `curtain_level` | положение шторы 0–100% |
| `curtain_status` | `open`, `close`, `stop`, `auto` |
| `brightness` | яркость подсветки шлюза |
| `rgb` | цвет подсветки в HEX без `#` |
| `ringtone` | мелодия: номер и громкость через запятую |
| `command` | произвольная команда протокола (`read`, `write`, …) |

Команда записи подписывается ключом шлюза. Если ключ не задан или неверный,
шлюз не выполнит запись — проверьте карточку шлюза.

## Чего избегать

- Не пишите в `propertySetHandle` то же свойство, которое вызвало обработчик:
  MajorDoMo остановит цепочку.
- Не привязывайте одно свойство объекта к нескольким метрикам: команды будут
  конкурировать.
- Не удаляйте служебные строки без необходимости: они появляются снова после
  сообщения шлюза.
